# E-commerce Data Warehouse Pipeline

##  О чем проект?

Это проект по очистке и подготовке данных для анализа. Данные пришли из разных файлов и форматов, их нужно было привести в порядок, объединить и загрузить в БД для последующего анализа.

---

## 🔧 Первичная очистка.

### 1. Исправил ошибки в данных

Исходные данные были "грязные" — с дубликатами, пропусками, ошибками в датах. Вот что я пофиксил:

**Таблица клиентов (customers):**
- Удалил повторяющиеся записи
- Привел телефоны к единому формату (+7...)
- Заполнил пропуски в email словом "UNKNOWN"
- **Добавил клиента с ID=0** — для заказов, где клиент неизвестен (иначе БД будет ругаться)

**Таблица товаров (products):**
- Удалил лишние пробелы в названиях
- Заполнил пропущенные цены **медианой** по категории 

**Таблица заказов (orders):**
- Сгруппировал товары по заказам (один заказ может содержать несколько товаров)
- Посчитал общую сумму каждого заказа

**Таблица платежей (payments):**
- Удалил платежи с ошибочной суммой ("error_amount")
- Заполнил неизвестные способы оплаты как "UNKNOWN"

**Таблица событий (events):**
- Оставил все события (даже повторяющиеся клики — это нормальное поведение пользователей)
- Заменил тестовый ID=999999 на ID=0

### 2. Загрузил данные в БД

Создал 5 таблиц в PostgreSQL с правильными связями:
- `customers` (клиенты)
- `products` (товары)
- `orders` (заказы)
- `payments` (платежи)
- `events` (события: просмотры, добавления в корзину)

Проверил, что все связи работают — нет заказов без клиентов, платежей без заказов и т.д.

---

## ⚠️ Что пошло не так?

В момент проверки данных была обнаружена **серьезная проблема**:

**Суммы в заказах и платежах НЕ сходятся!**

- Заказ на 1000 рублей, а платеж на 5000 рублей или заказ в евро, а платеж в рублях
- Из 848 платежей **ни один** не совпадает с суммой заказа

  ## 📊 Что можно анализировать?

Несмотря на проблему с платежами, большинство данных **пригодны для анализа**:

✅ **Анализ клиентов**: кто сколько заказывает, какие клиенты самые активные  
✅ **Анализ товаров**: какие товары популярны, какие категории продаются лучше  
✅ **Анализ поведения**: что пользователи смотрят, что добавляют в корзину  
✅ **Анализ заказов**: сколько заказов в день, средний чек, популярные статусы

**Почему так?**
Скорее всего, данные были сгенерированы автоматически, и таблицы `orders` и `payments` создавались отдельно, без связи друг с другом. То, что таблицы вообще сгенерированы я понял не сразу :)

**Принятое решение**
Не придумывать "правильные" суммы, а честно задокументировать проблему. Для того чтобы завершить проект таблица **ordres** будет синтетически сгенерирована таким образом, чтобы можно было анализировать экономическую часть.
**Важно отметить**, что в работе с реальными данными такое действие **недопустимо** по понятным причинам. Однако, проект закончить хочется и интересно посмотреть, что получится :)
