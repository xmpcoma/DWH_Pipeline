# E-commerce Data Warehouse Pipeline

## 📌 Описание проекта

ETL-пайплайн для очистки, преобразования и загрузки данных из разрозненных источников (CSV, JSON, XML, Excel) в PostgreSQL для последующего анализа.

### Источники данных:
- `customers.csv` - информация о клиентах
- `orders.json` - заказы
- `payments.csv` - платежи
- `products.xlsx` - товары
- `events.xml` - события (просмотры, добавления в корзину)

## 🚨 КРИТИЧЕСКАЯ ПРОБЛЕМА: Таблица payments

### Что обнаружено:

В ходе валидации, после очистки данных, выявлена **фундаментальная проблема** с исходными данными платежей:

1. **Суммы не сходятся**: Из 968 платежей **ни один** не совпадает с суммой заказа
2. **Валюты не совпадают**: Заказ в EUR, платеж в RUB (и наоборот)
3. **Процент совпадений: 0%**

### Причина:
Вероятно таблицы `orders` и `payments` были сгенерированы **независимо друг от друга** без соблюдения бизнес-логики.

### Решение:

**ТАБЛИЦА payments СГЕНЕРИРОВАНА ЗАНОВО** на основе таблицы `orders`. 
Понятно, что при работе с реальными данными такое решение **недопустимо**, однако это единственный способ закончить проект. Таблица была сгенерирована по таким параметрам:

# Берем только не-отмененные заказы
valid_orders = orders[orders['status'] != 'cancelled']
